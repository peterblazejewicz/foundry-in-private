# contracts/

The cell's interface objects (architecture §7) as JSON Schema (draft 2020-12). This folder is the only source.

| Object | Schema | Producer → consumer |
|---|---|---|
| `vision.inspect` result | `vision-inspect-result.schema.json` (1.0.0) | board A → board B |
| Finding | `finding.schema.json` (to write) | board B → SQLite, AI Search |
| Approval card / decision | `approval.schema.json` (to write) | board B ⇄ screen B |
| Actuation command / ack | `actuation.schema.json` (to write) | board B ⇄ MCU |
| Screen IPC messages | to be chosen in the spec (JSON Schema or `.proto`) | Python ⇄ Avalonia |

- The version is in `$id` (`urn:foundry-in-private:contracts:<name>:<semver>`).
- Each schema has a `title`. Each `$defs` entry has a `title`. The C# type names come from them.
- `examples/`: one valid JSON file per object. Contract tests validate them and round-trip them.
- Generated Python models: `edge/shared/src/cell_shared/contracts/`. Generated C# models: `screens/src/Screen.Core/Contracts/`. Do not edit them.
- Use the `contract-change` skill for every change.

## Generate

Run from the repo root after each schema change:

| Models | Write | Check (exit 1 when out of date) |
|---|---|---|
| Python (pydantic v2, datamodel-code-generator) | `uv run python contracts/generate_python.py` | `uv run python contracts/generate_python.py --check` (also a pytest test) |
| C# (System.Text.Json, NJsonSchema) | `dotnet run --project screens/tools/ContractGen` | `dotnet run --project screens/tools/ContractGen -- --check` (also a CI step) |

The generator versions are pinned (`pyproject.toml`, `screens/Directory.Packages.props`). A version change can change the output. Regenerate in the same commit.

## Limits

- pydantic does not take `pattern` on a date-time. The Python model accepts any timezone offset on `captured_at`. The schema accepts `Z` only.
- C#: read and write contract objects with `Screen.Core.ContractJson.Options`. They refuse a missing, null or unknown field and a null list element. They read only date-times that end in `Z`, and write UTC with `Z`. They do not check ranges, lengths or other patterns. Board B validates each object before it sends it.
- JSON Schema does not express these rules. The producer must keep them: crop count equals detection count; `x_max > x_min` and `y_max > y_min`; detections in descending confidence order.

## Quality-bar exception (hard rule 5)

The generated C# files start with `<auto-generated>` and hold `#pragma warning disable`. NJsonSchema writes both, and no setting removes them. Reason: the files are generator output, never edited by hand, and checked for drift in CI. The xUnit contract tests cover their behaviour. Hand-written C# keeps the full analyzer set.
